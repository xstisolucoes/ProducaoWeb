Relatório de Auditoria de Segurança

ProducaoWeb — Sistema de Gestão de Produção

Data da Auditoria: 2026-11-18

Escopo Auditado: Código-fonte completo (backend, frontend, configurações, infraestrutura)

Nota Metodológica: Análise estática de código (white-box) baseada em 5 categorias de vulnerabilidade adaptadas à stack: Chaves Expostas, Permissão Definida no Navegador, IDOR, Banco Sem Tranca (RLS), Inputs Sem Tratamento (XSS). Stack detectada: TypeScript, React 19, Vite, Express, tRPC, Drizzle ORM, Firebird, MySQL, JWT (jose), OAuth2.

Principais Riscos Críticos:

  • Exposição de segredos em repositório Git: JWT_SECRET, chaves de API, tokens de banco, senhas padrão — permite comprometimento total da autenticação e acesso ao banco de dados.
  • Ausência de middleware de autorização: Roles (admin, programmer, operator) não são validadas centralmente; dependem de código manual em cada rota.

Pontos Fortes: 7 mecanismos de segurança bem implementados (autenticação JWT, isolamento por máquina, validação Zod, cookies seguros, OAuth externo, rate limiting no proxy, sanitização de inputs).

Pontos Fracos (Principais Riscos)

  1. Segredos (JWT_SECRET, API Keys, DB passwords) commitados no repositório Git (.project-config.json, .env)
  2. Ausência de camada de autorização centralizada (RBAC) — validação manual propensa a erros
  3. Endpoints de listagem expõem dados globais sem filtro de tenant/máquina (dashboard, produtos, estoque, clientes)
  4. IDOR em consulta de cliente por ID e atualização de status de pedido sem validação de propriedade
  5. Validação de startup ausente para credenciais padrão/inseguras

Validação de Startup Ausente para Credenciais Padrão/Inseguras
Alta

export function getFirebirdProxyConfiguration(env) {
  const rawUrl = env.FIREBIRD_PROXY_URL?.trim();
  const token = env.FIREBIRD_PROXY_TOKEN?.trim();
  if (!rawUrl) throw new Error("FIREBIRD_PROXY_URL não foi configurada.");
  if (!token) throw new Error("FIREBIRD_PROXY_TOKEN não foi configurada.");
  // Não valida se token é "crie-um-token-longo" ou "masterkey"
}
Impacto: Sistema pode rodar em produção com credenciais padrão/fracos conhecidos.

Recomendações Priorizadas

P1 - Crítica Remover Imediatamente Todos os Segredos do Repositório Git

  1. Revogar e rotacionar TODAS as chaves expostas: JWT_SECRET, FIREBIRD_PROXY_TOKEN, FIREBIRD_PASSWORD, BUILT_IN_FORGE_API_KEY, OAUTH_SERVER_URL.
  2. Remover .project-config.json do histórico Git (use git filter-repo ou BFG Repo-Cleaner).
  3. Remover .env do histórico Git e adicionar ao .gitignore.
  4. Configurar variáveis de ambiente no ambiente de deploy.
  5. Implementar pre-commit hooks (husky + secretlint) para impedir commits futuros com segredos.

P1 - Crítica Implementar Middleware de Autorização Centralizado (RBAC)

  1. Criar procedimentos tRPC reais com middleware que validem ctx.user.role e ctx.localUser.operationalProfile.
  2. Remover validações manuais (throw new Error) das rotas individuais.
  3. Implementar testes automatizados de autorização para cada role.
  4. Documentar matriz de permissões por role/endpoint.

P2 - Alta Validar Segurança de Credenciais no Startup

  1. Em getFirebirdProxyConfiguration: rejeitar tokens que correspondam a placeholders conhecidos ("crie-um-token-longo", "changeme", "default").
  2. Validar que FIREBIRD_PASSWORD não seja "masterkey" ou outras senhas padrão conhecidas.
  3. Log de warning crítico se credenciais inseguras detectadas em produção (NODE_ENV=production).

P2 - Alta Implementar Filtro de Tenant/Empresa nas Consultas

  1. Adicionar companyCode/machineCode como filtro obrigatório em getOrders, getProducts, getStock, getProductionDashboard.
  2. Para usuários programmer/admin, permitir visualização global (opcional). Para operator, filtrar estritamente pela máquina.
  3. Aplicar mesmo filtro em participants.list (filtrar por companyCode do usuário).

P2 - Alta Corrigir IDOR em Endpoints de Detalhe

  1. Em participants.client: validar se cliente.codigo pertence à companyCode do usuário antes de retornar.
  2. Em orders.updateStatus: validar se opCodigo/mpCodigo pertence a uma máquina controlada pelo usuário.

P3 - Média Hardening Adicional

  1. Adicionar Content Security Policy (CSP) headers no Express (helmet.js).
  2. Implementar rate limiting global no Express (express-rate-limit).
  3. Adicionar validação de origem (CORS) restritiva.
  4. Mover dangerouslySetInnerHTML no ChartStyle para CSS-in-JS ou style tags seguras.
